## 1. 반영할 결정

### S1. F03 몬스터 — 스폰 구간별 체력 배율 (`spec/F03-monsters.md`)

사용자 결정(2026-11-10 확정): 게임 시간이 지날수록 몬스터 체력이 오른다. 방식은 **스폰 테이블 구간별 배율**이다.

규칙(수용 기준으로 옮긴다):
1. 스폰 테이블의 각 구간(0~2, 2~5, 5~8, 8~10분)에 체력 배율 `hpMultiplier`가 있다(F11 스키마, S2). 생략하면 1.0.
2. 몬스터가 **스폰되는 스텝**에 속한 구간의 배율을 정의 체력에 곱해 그 몬스터의 최대 체력과 현재 체력으로 삼는다. 그 뒤 구간이 바뀌어도 **이미 살아 있는 몬스터의 체력은 바뀌지 않는다**(3.0 F 결정론과 상태 해시 보존 — 체력은 해시에 들어간다).
3. **보스(M4)와 보스가 소환한 몬스터는 배율을 적용하지 않는다**(정의 체력 그대로) [PM 기본값].
4. 같은 시드·같은 데이터로 두 번 실행하면 스폰된 각 몬스터의 체력이 동일해야 한다(결정론 기준에 배율이 포함됨을 명시).
5. 배율 적용 뒤 체력의 반올림은 하지 않는다(정의 체력 × 배율을 그대로 — 정의 체력이 정수여도 결과는 실수) [PM 기본값]. 단, F11 로드 시 초→스텝 변환처럼 미리 계산할 수 있는 것은 그렇게 해도 된다는 기존 규칙이 있으면 그 표현을 따른다.
6. 데이터 초기값 예시: 1.0 / 1.5 / 2.2 / 3.0(사용자 조정 대상 — "스폰 속도 조정은 나중에").

F03 요구사항 문단(첫 단락 "정의 값(체력, …)은 F11 스키마로 로드된 값을 사용한다")에 "체력은 스폰 구간의 배율을 곱한 값(11회차)"을 한 구절로 보강한다. 스폰 수 검증 기준(10회차 보강 항목)은 손대지 않는다.

### S2. F11 데이터 — 스폰 테이블 스키마 확장 (`spec/F11-data-driven.md`)

- 스폰 테이블 구간 객체에 선택 필드 `hpMultiplier`(실수, 생략 시 1.0)를 추가한다. 현재 구간 구조는 `segments[]: { startSeconds, endSeconds, spawnsPerSecond, entries[]: { monsterId, weight } }`다(정확한 키 이름은 TECH가 소유 — SPEC에는 "구간마다 체력 배율 필드(선택, 기본 1.0)"로 적는다).
- 검증: 배율이 **양의 유한 실수가 아니면**(0 이하, NaN, 무한) 그 값은 검증 오류다. 처리 방식은 F11의 기존 "객체별 불변식 2단 검증"(Q35) 규칙을 따른다 — 기존 기준이 "해당 객체 무효"인지 "파일 전체 거부"인지 F11 본문에서 확인해 **같은 처리**로 적는다(새 처리 방식을 만들지 않는다). 모호하면 보고에.
- 핫 리로드(Q43 "다음 스폰부터 적용")는 자연스럽게 성립한다(배율은 스폰 시점에만 읽음) — 기존 Q43 기준 문장에 괄호 한 구절.
- "JSON 편집만으로 바뀌어야 한다" 기준 목록에 배율을 포함한다(기존 문장 보강, 새 기준 불필요).

### S3. F08 HUD — 보유 무기·패시브 레벨과 체력 배율 표시 (`spec/F08-stage-flow.md`)

사용자 결정(2026-11-10 확정, "3번"): 일반 플레이 HUD에 **텍스트 패널**로 상시 표시. 아이콘 슬롯 바는 **나중 후보**로 기록만.

수용 기준으로 옮긴다(현재 F08의 HUD 관련 기준은 "경과 시간 표시" 한 줄뿐이다 — 그 근처에 둔다):
1. 플레이 중 HUD에 보유 무기가 **한 줄씩** "무기 표시 이름 Lv n" 형식으로 표시되어야 한다. 표시 이름은 F11 정의의 `displayName`이다. 진화 무기(E1·E2)는 단계가 없으므로 "Lv n" 대신 "(진화)"를 표시한다.
2. 보유 패시브도 같은 형식으로 무기 아래에 표시되어야 한다. 보유하지 않은 슬롯은 표시하지 않는다.
3. 마지막 줄에 **현재 스폰 구간의 몬스터 체력 배율**이 "몬스터 체력 ×1.5" 형식(소수점 1자리, InvariantCulture)으로 표시되어야 한다 [PM 기본값: 소수 1자리]. 구간이 바뀌면 다음 프레임 안에 갱신된다.
4. 레벨업 선택을 적용한 뒤 **다음 프레임 안에** 패널이 새 레벨을 반영해야 한다. 판 시작 시에는 시작 무기와 레벨 1이 표시된다.
5. 패널 표시·갱신은 시뮬레이션 상태에 영향을 주지 않아야 한다(읽기 전용 — 3.0 F·상태 해시 불변).
6. 위치는 화면 왼쪽 아래 [PM 기본값], 기존 네 항목(시간·레벨·체력·경험치)은 그대로.

"나중 후보" 기록: F08 끝의 미확정/후보 자리(없으면 `spec/90-open-questions.md` Q49 안에) — "아이콘 슬롯 바(무기 4 + 패시브 3, 색 아이콘 + 레벨 숫자)는 1차 MVP 범위 밖, 무기 아이콘 키·레지스트리 확장이 선행 조건".

### S4. F19 개발자 모드 — 오버레이 현황 패널과 언어·폰트 (`spec/F19-dev-mode.md`)

사용자 결정(2026-11-10 확정): ① 오버레이 레이블은 **영어**, 폰트는 **OS 폰트**("Malgun Gothic", 없으면 엔진 기본 폰트, 자산 추가 없음). ② 개발자 도구로 동작·버그를 확인할 때 **보유 스킬과 기타 현황이 반드시 표시**되어야 한다.

반영:
1. 오버레이 항목 목록(현재 "시각화 / 시간 제어 / 상태 조작 / 데이터" 묶음)에 **현황 패널** 묶음을 신설: 보유 무기·패시브와 레벨(진화 표기 포함), 현재 몬스터 체력 배율, 게임 시간과 스텝 번호, 판 시드, 생존 몬스터 수(보스 포함), 활성 젬 수, 현재 전략 조합 4종, 실제 배속(기존 "오버레이에 실제 배속 표시"와 중복되지 않게 통합).
2. 수용 기준(11회차 신규): 오버레이가 열려 있는 동안 위 항목이 표시되고 매 프레임 갱신되어야 한다. 오버레이가 닫혀 있으면 비용이 0이어야 한다(기존 "숨기면 호출 0" 규칙에 포함시키되 문장으로 명시). 현황 패널은 읽기 전용이며 시뮬레이션 상태를 바꾸지 않는다.
3. 수용 기준(11회차 신규): 오버레이의 레이블은 영어이며, 데이터에서 온 한글 문자열(무기·패시브 `displayName`)은 OS 폰트로 렌더링된다. OS 폰트를 만들 수 없는 환경에서는 엔진 기본 폰트로 표시되며 이때 한글이 깨져 보이는 것은 허용된다(개발자 도구).
4. 기존 F19 본문에 "한국어 레이블"이라는 표현이 있으면 정정한다(현재 SPEC에는 UI 언어 규칙이 없으므로 충돌은 아님 — 보고에 "있었음/없었음"만).
5. 측정 시작 가드(5·8회차 기준)와의 관계: 측정 중에는 오버레이가 숨겨지므로 현황 패널도 숨겨진다 — 기존 규칙으로 충분, 새 기준 없음. 다만 "측정 시작 거부 조건"에 현황 패널은 들어가지 않는다는 한 구절.
