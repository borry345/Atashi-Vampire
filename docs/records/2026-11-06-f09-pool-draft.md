## README 쪽 요약 (풀링 절)

```markdown
### 오브젝트 풀링 (F9)

게임 코드는 `IPoolStrategy` 인터페이스만 알고, 호출은 `EntityLifecycle` 한 곳에서만 한다. 구현은 세 가지이며 서로 교체할 수 있다.

- **A. 자체 풀 (`CustomPoolStrategy`)**: 템플릿마다 비활성 인스턴스를 스택(LIFO)에 쌓아 둔다. 반환한 인스턴스는 다음 요청에 그대로 다시 나간다. 스택이 비면 새로 생성하고 상한은 없다.
- **B. 생성·파괴 (`InstantiatePoolStrategy`)**: 풀이 없는 기준선이다. 요청마다 `Instantiate`하고, 반환마다 비활성화한 뒤 `Destroy`한다.
- **C. Unity 내장 풀 (`UnityObjectPoolStrategy`)**: 템플릿마다 `UnityEngine.Pool.ObjectPool<GameObject>`를 하나씩 둔다(`collectionCheck: true`, `maxSize: int.MaxValue`).
- **A와 C의 차이**: 둘 다 "비활성 인스턴스를 모아 두었다가 다시 쓴다"는 점은 같다. 차이는 세 가지다.
  - 재사용 순서: A는 직접 짠 LIFO라서 순서가 코드에 드러난다. C는 Unity 내부 구현을 따른다. 실측한 C의 순서는 LIFO도 FIFO도 아니었지만 매번 같았다(결정적).
  - 미리 생성: C에는 미리 생성하는 API가 없어서, 꺼냈다가 되돌려 넣는 방식으로 대신했다.
  - 중복 반환 검사: C는 `collectionCheck`가 중복 반환을 `InvalidOperationException`으로 잡는다. 하지만 풀에서 나오지 않은 객체가 들어오는 것은 잡지 못한다. 그래서 세 구현 모두 공통 소유자 검사를 앞에 두었다.
- 풀은 상태를 초기화하지 않는다. 초기화는 `EntityLifecycle`이 맡으므로, 어떤 전략을 쓰든 같은 초기화가 보장된다.
- 풀 전략 전환은 다음 판 시작 시점에 적용된다. 전환 방법은 App(토글 UI·설정)이 구현된 뒤 이 절에 적는다.
```

(마지막 줄의 전환 방법은 SPEC F9가 README에 기록하라고 요구하는 항목. 토글은 App 몫이라 구현자가 내용을 정하지 않았다.)

## devlog 쪽 초안 (측정 항목)

```markdown
## 측정 F9: 오브젝트 풀 전략 A/B/C

**가설**
- B(생성·파괴)는 요청과 반환마다 객체를 할당하고 해제한다. 그래서 GC로 인한 간헐적 프레임 스파이크가 생기고, 평균보다 1% low(최악 프레임 시간)가 더 나빠질 것이다.
- A와 C는 둘 다 재사용 구조여서 정상 상태에서는 할당이 거의 없다. 따라서 1% low는 B보다 좋고, A와 C끼리는 차이가 작을 것이다.
- C는 `collectionCheck: true`라서 반환할 때마다 검사 비용이 든다. 이 비용이 반환이 많은 구간에서 A와 C의 차이로 드러나는지 본다. 검사 비용의 크기는 아직 재지 않았다.

**사전 실측 (구현 단계, Unity 6000.3.28f1, batchmode PlayMode 테스트 84건 3회 연속 통과)**
- U22: B에서 `Destroy`는 1프레임 뒤에 적용됐다. 같은 프레임 안에서는 객체가 남아 있지만, 먼저 비활성화했기 때문에 활성 객체 검색에 잡히지 않았다. 즉 같은 프레임의 다음 스텝에 간섭하지 않는다.
- U21:
  - `collectionCheck: true`에서 중복 반환하면 `InvalidOperationException`이 난다.
  - `collectionCheck: false`에서 중복 반환하면 예외 없이 같은 객체가 두 번 쌓인다.
  - 풀에서 나오지 않은 객체를 반환하면 `collectionCheck: true`여도 받아들여진다.
  - `maxSize: int.MaxValue`에서 1000개를 반환하면 모두 보관되고 파괴는 0회다. 대조로 `maxSize: 2`에서 3개를 반환하면 1개가 파괴됐다.
- 재사용 순서(같은 획득·반환 시퀀스): A는 `0,1,2,0,1,3,3,1`(LIFO), C는 `0,1,2,1,0,3,2,3`이었다. 두 전략 모두 반복 실행에서 결과가 같았다.

**결과**: (사용자 측정 후 기입: F10 측정 CSV, 평균 프레임 시간, 1% low, `Survivor.Pool` 마커 시간)

**해석**: (사용자 측정 후 기입)
```
