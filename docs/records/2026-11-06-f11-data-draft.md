## A. README 요약

```markdown
## 데이터 기반 설계 (F11)
- 게임 데이터 7종은 `StreamingAssets/Data/`의 JSON 파일이다. 빌드 폴더(`<게임>_Data/StreamingAssets/Data/`)에서 바로 편집할 수 있고, 다시 실행하면 반영된다.
- 파싱은 Newtonsoft, 필드 바인딩·검증은 직접 작성한 코드(`Survivor.Data`)가 한다. 파일은 UTF-8이어야 한다(BOM 허용, 깨진 글자가 있으면 "인코딩 오류 가능" 경고).
- 필수 4종(weapons, monsters, spawnTable, playerStats)이 없거나 깨지면 시작을 차단하고 화면에 원인을 표시한다. 선택 3종(combinations, passives, levelUpPool)은 경고 후 기본값으로 진행한다.
- 정의 하나가 틀리면 그 정의만 건너뛰고 경고한다(플레이어 기본 스탯은 예외: 오류면 차단). 알 수 없는 키는 경고 후 무시한다.
- **코드 수정 없이 추가할 수 있는 범위**: 기존 행동 타입(무기 projectile/homing/orbit/zone, 몬스터 chaser/charger/ranged/boss)의 파라미터 조합까지다. 새 행동 타입(예: 벽에 튕기는 투사체, 포위 AI)은 코드 추가가 필요하다.
- 시각 자원은 문자열 키(`assetKey`)로만 참조한다. 키는 `Resources/AssetKeyRegistry.asset`에 등록하고, 등록되지 않은 키는 마젠타 원으로 대체되며 경고가 남는다.
- 스키마 상세: `docs/data-schema.md`(아래 B).
```

## B. docs 스키마 설명 (`docs/data-schema.md` 초안)

```markdown
# 데이터 스키마 (StreamingAssets/Data)
공통: 최상위는 객체이고 `"schemaVersion": 1`이 필수다(없거나 1이 아니면 파일 단위 실패). ID는 `^[A-Za-z0-9_]+$`이고 대소문자를 구분한다. 정수 필드에 소수(2.0 포함)를 쓰면 타입 오류다.
단위: `...Seconds`는 초로 쓰고 로드할 때 스텝(1/60초)으로 바뀐다. 속도는 초당 유닛, 각속도는 초당 도, 거리·반지름은 월드 유닛이다.

| 파일 | 구분 | 파일 단위 실패 | 정의 단위 오류 |
|---|---|---|---|
| weapons.json | 필수 | 차단 | 그 무기만 건너뜀(경고) |
| monsters.json | 필수 | 차단 | 그 몬스터만 건너뜀(경고) |
| spawnTable.json | 필수 | 차단 | 최상위 필드 오류는 차단, 구간·항목 오류는 그것만 건너뜀 |
| playerStats.json | 필수 | 차단 | 어떤 오류든 차단(기본값으로 대체하지 않음) |
| combinations.json | 선택 | 경고 후 진화 없음 | 그 규칙만 건너뜀 |
| passives.json | 선택 | 경고 후 패시브 없음(조합 규칙도 전부 무효) | 그 패시브만 건너뜀 |
| levelUpPool.json | 선택 | 경고 후 균등 가중치(회복은 체력 비율 가중 유지) | 최상위 오류는 균등 폴백, 규칙 오류는 그 규칙만 건너뜀 |

**weapons.json** `weapons[]`: `id`, `displayName`, `behavior`(projectile/homing/orbit/zone), `assetKey`는 필수. `iconKey`(없으면 assetKey)와 `evolvedOnly`(기본 false)는 선택. `levels`는 기본 무기 정확히 5개, 진화 무기 정확히 1개이고, 각 단계 값은 절대값이다.
- 공통: `damage`>0
- projectile/homing: `cooldownSeconds`, `projectileSpeed`, `projectileRadius`, `lifetimeSeconds`. 선택은 `projectileCount`(1), `spreadDegrees`(0), `pierceCount`(0)
- orbit: `orbCount`, `orbRadius`, `orbitRadius`, `angularSpeedDegPerSec`, `hitIntervalSeconds`
- zone: `cooldownSeconds`, `zoneRadius`, `durationSeconds`, `hitIntervalSeconds`. 선택은 `placement`(nearestEnemy/player, 기본 nearestEnemy)
- 다른 행동 타입의 키는 경고 후 무시한다.

**monsters.json** `monsters[]`: `id`, `displayName`, `assetKey`, `behavior`(chaser/charger/ranged/boss), `maxHealth`>0, `moveSpeed`≥0, `radius`>0, `contactDamage`≥0.
- charger는 `charge{triggerDistance, chargeSpeed, durationSeconds, cooldownSeconds}`
- ranged는 `ranged{attackRange, fireCooldownSeconds, projectile{assetKey, speed, radius, damage, lifetimeSeconds}}`
- boss는 `bossPatterns[]`가 1개 이상. 패턴은 `hazardZone{cooldownSeconds, zoneRadius, durationSeconds, damage, assetKey, placement(기본 player)}` 또는 `summon{cooldownSeconds, monsterId, count, summonRadius}`이고, summon의 `monsterId`는 boss가 아닌 유효 몬스터여야 한다.

**spawnTable.json**: `despawnDistance`(>20), `bossMonsterId`, `segments[]`(1개 이상)는 필수.
- 구간은 `startSeconds`, `endSeconds`, `spawnsPerSecond`>0, `entries[{monsterId, weight>0}]`이다. 시간 오름차순이고 겹치면 안 된다.
- 600초를 넘는 `endSeconds`는 600으로 잘리고 경고가 남는다.
- boss 몬스터는 `entries`에 넣을 수 없다.
- `bossMonsterId`가 무효면 경고만 남고 보스가 나오지 않는다(10분 클리어 불가).

**passives.json** `passives[]`: `id`, `displayName`, `iconKey`, `stat`(attackSpeed/moveSpeed/pickupRadius), `levels`는 정확히 5개이고 각 `{bonus≥0}`. bonus는 누적 절대 비율이다(0.10 = +10%).

**combinations.json** `combinations[]`: `id`, `weaponId`(진화 전용이 아닌 무기), `passiveId`, `resultWeaponId`(evolvedOnly 무기). 같은 weaponId를 쓰는 규칙이 둘이면 둘째를 건너뛴다.

**levelUpPool.json**: `defaultWeight`>0와 `healBaseWeight`≥0는 필수. `rules[{kind(weaponNew/weaponUpgrade/passiveNew/passiveUpgrade), targetId(ID 또는 "*"), weight≥0}]`는 선택이다. 구체 ID 규칙이 `"*"`보다 우선한다.

**playerStats.json**(전부 필수): `maxHealth`, `moveSpeed`, `radius`, `pickupRadius`, `invulnerabilitySeconds`(≥0, 0 허용), `startingWeaponId`(진화 전용이 아닌 유효 무기, 무효면 차단), `xpCurve{thresholds:int[](각 ≥1), growthAfterTable:int}`, `pickups{gemAssetKey, gemRadius, gemXpValue:int, gemAttractSpeed, chestAssetKey, chestRadius}`.

**초→스텝 환산** (반올림, 최소 1): 무기 `cooldownSeconds`·`lifetimeSeconds`·`hitIntervalSeconds`·`durationSeconds`, 몬스터 `charge.durationSeconds`·`charge.cooldownSeconds`·`ranged.fireCooldownSeconds`·`projectile.lifetimeSeconds`, 보스 패턴 `cooldownSeconds`·`durationSeconds`.
**초→스텝 환산** (0 허용): `invulnerabilitySeconds`, 스폰 `startSeconds`·`endSeconds`.

**플레이 불가(시작 차단)**: 다음 중 하나라도 해당하면 시작을 차단한다.
- 사용 가능한 무기 0개
- 스폰 테이블이 참조하는 유효 몬스터 0종
- 플레이어 기본 스탯 없음
- 스폰 테이블 없음

**터널링 검사**: 이동 객체마다 `속도/60 ≤ 반지름`을 검사한다. 위반은 경고만 남기고 시작은 막지 않는다.
- 궤도 원의 속도는 각속도×궤도 반지름 + 플레이어 최대 속도(P2 최대 단계 적용)로 계산한다.
```

## C. "JSON만으로 추가" 시연 절차 (사용자 수행용, 결과 기록은 사용자)

1. 빌드 폴더의 `StreamingAssets/Data/monsters.json`에 기존 행동 타입의 새 몬스터를 하나 넣습니다. 예: `{ "id": "M5", "displayName": "거인 좀비", "behavior": "chaser", "assetKey": "shape.monster.green", "maxHealth": 300, "moveSpeed": 2, "radius": 0.6, "contactDamage": 10 }`
2. 같은 폴더의 `spawnTable.json`에서 원하는 구간의 `entries`에 `{ "monsterId": "M5", "weight": 1 }`을 넣습니다.
3. (선택) `weapons.json`에 `projectile` 행동의 새 무기를 넣습니다. 단계는 정확히 5개여야 합니다.
4. 게임을 다시 실행해 확인합니다. 콘솔(Player.log) 첫 로드 줄에 `[Data] 데이터 로드 완료: 파일 7/7, ... 몬스터 5`가 나와야 합니다. 그다음 해당 시간대에 M5가 등장하는지, 새 무기가 선택지에 뜨는지 봅니다.
5. 실패 사례도 함께 시연합니다. 필수 필드를 하나 지우면 그 정의만 빠지고 경고가 남습니다. 중괄호를 하나 지워 필수 파일 문법을 깨면 시작 차단 화면이 나옵니다.

`assetKey`가 레지스트리에 없으면 마젠타 원으로 표시되고 키 이름이 담긴 경고가 남습니다. 단, 키 검증 경고가 로드 때 남으려면 부팅 코드(FLOW)가 `AssetKeyResolver.ValidateKeys`를 호출해야 합니다. **이 호출 여부는 미확정** — IMP-FLOW 브리핑에 명시할 것(PM 메모).
