### 5.7 타깃 공급자 (Core 계약, IMP-SPATIAL 구현)

```csharp
namespace Survivor.Core
{
    public enum TargetProviderKind { BruteForce = 0, SpatialHash = 1, Physics2DQuery = 2 }

    public struct MonsterSnapshot
    {
        public EntityHandle Id;
        public Vector2 Position;
        public float Radius;
        public bool IsLarge;          // (rev 3) MonsterSizeRules.IsLarge(Radius, isBoss): kept out of the spatial hash
    }

    /// Frozen monster positions for this step, filled in BuildIndex in ascending Id order.
    public sealed class MonsterSnapshotBuffer
    {
        public int Count { get; }
        public ref readonly MonsterSnapshot this[int index] { get; }
        public float MaxHashedRadius { get; }          // max Radius over !IsLarge entries
        public Rect Bounds { get; }                    // (rev 2) AABB of all positions; used by Physics2DTargetProvider
        public bool TryGetIndex(EntityHandle id, out int index);
        public void Clear();
        public void Add(in MonsterSnapshot snapshot);  // must be called in ascending Id order
    }

    public readonly struct TargetHit
    {
        public readonly EntityHandle Id;
        public readonly Vector2 Position;
        public readonly float DistanceSquared;
        public TargetHit(EntityHandle id, Vector2 position, float distanceSquared);   // (rev 13)
    }

    /// Nearest-monster query for weapons only (monsters use StepContext.PlayerPosition); all implementations must return identical results.
    public interface ITargetProvider
    {
        TargetProviderKind Kind { get; }
        void OnSnapshotBuilt(MonsterSnapshotBuffer snapshot);   // once per step in BuildIndex
        bool TryFindNearest(Vector2 point, out TargetHit hit);  // false when no monster exists; never throws
    }
}

namespace Survivor.Strategies
{
    /// Shared monster spatial hash; rebuilt at most once per step, reused by SpatialHashTargetProvider and SelfCollisionStrategy.
    public sealed class MonsterSpatialIndex : IStepPhaseHandler    // BuildIndex order 10
    {
        public MonsterSpatialIndex(float cellSize, MonsterSnapshotBuffer snapshot);
        public bool Required { get; set; }                          // set by composition root / target switch
        public float CellSize { get; }
        public void OnPhase(SimulationPhase phase, in StepContext context);   // Rebuild when Required
        public void QueryCircle(Vector2 center, float radius, List<int> snapshotIndicesOut); // includes all IsLarge entries; (rev 14) clears first, superset, ascending
        public void ForEachRing(Vector2 point, int ring, List<int> snapshotIndicesOut);       // for nearest search; (rev 14) clears first, ring < 0 throws
        public void Clear();                                        // (rev 3) run reset; (rev 8) called by App right after RunSession.Reset(in RunStrategies), before Open (TAC-F8-2)
        public IReadOnlyDictionary<long, int> CellCounts { get; }   // dev visualization; (rev 14) computed lazily after a rebuild, then cached
        // (rev 14) ctor throws ArgumentOutOfRangeException unless cellSize is positive and finite, ArgumentNullException when snapshot is null
    }

    public sealed class SpatialHash   // generic center-point hash, also used for gems/chests
    {
        public SpatialHash(float cellSize);                         // (rev 14) ArgumentOutOfRangeException unless SpatialHashSettings.IsValidCellSize(cellSize)
        public float CellSize { get; }                              // ★ (rev 14)
        public int Count { get; }                                   // ★ (rev 14) payloads inserted since the last Clear
        public static long CellOf(Vector2 p, float cellSize);       // R14
        public static long KeyOf(int cx, int cy);                   // R14
        public void Clear();
        public void Insert(int payload, Vector2 position);
        public void QueryCells(Vector2 center, float radius, List<int> payloadsOut);   // (rev 14) clears first; cells of the square [center ± radius] clipped to the occupied range; superset
    }

    /// (rev 14) Code as implemented (TAC-F16-4).
    public sealed class SpatialHashSettings
    {
        public float CellSize { get; set; }                         // default StrategySelection.DefaultSpatialHashCellSize; setter throws ArgumentOutOfRangeException when invalid
        public static bool IsValidCellSize(float cellSize);         // ★ (rev 14) false for 0, negative, NaN, ±Infinity
    }

    public sealed class BruteForceTargetProvider : ITargetProvider { }   // A: full scan with TargetOrdering.IsBetter (R6)
    public sealed class SpatialHashTargetProvider : ITargetProvider      // B
    {
        public SpatialHashTargetProvider(MonsterSpatialIndex index);   // (rev 14) null -> ArgumentNullException
    }
}
```

- 구현 클래스: `BruteForceTargetProvider`, `SpatialHashTargetProvider(MonsterSpatialIndex)`, `Physics2DTargetProvider(PhysicsBodySynchronizer bodies, int monsterLayerMask)`(TAC-F16-3). (14회차) 웨이브 2a에서 구현된 것은 A·B뿐이다. C(`Physics2DTargetProvider`)는 IMP-COLLISION(웨이브 3) 소유 `PhysicsBodySynchronizer.TryGetBody`(5.9.1)에 의존하므로 웨이브 3으로 이월했다(5c.4). 네임스페이스는 A·B·`MonsterSpatialIndex`·`SpatialHash`·`SpatialHashSettings` 모두 `Survivor.Strategies`다(폴더는 `Spatial/`·`Targeting/`).
- `TargetProviderSlot : ITargetProvider`(Simulation/Loop, IMP-LOOP)가 현재 공급자를 감싸고 `StepContext.Targets`로 나간다. 교체는 `Begin`의 `SwitchTargetProvider` 대기 명령에서만 한다(TAC-F16-5).
- (11회차, 참조 방향 해소) 교체 명령은 Strategies 구체 클래스를 Simulation이 부르지 않도록 **App이 만든 공급자 인스턴스와 요구사항 적용 콜백을 담아** 온다(TAC-F8-2 8회차와 같은 해법). 아래 셋이 이 회차에 시그니처를 정한 것이다(★ = 이 회차 신규 이름, 나머지는 기존 이름):

```csharp
namespace Survivor.Simulation
{
    /// ★ (rev 11) Payload of the Begin-phase SwitchTargetProvider pending command. Built by App (IMP-FLOW), applied by PendingCommandQueue (IMP-LOOP).
    public readonly struct SwitchTargetProviderCommand          // file: Scripts/Simulation/Loop/SwitchTargetProviderCommand.cs (IMP-LOOP)
    {
        public readonly ITargetProvider Provider;            // new provider instance (Core interface), created by App's StrategyFactory
        public readonly Action ApplyRequirements;            // App closure (same one used at run start, TAC-F8-2): recompute MonsterSpatialIndex.Required,
                                                             // then PhysicsBodySynchronizer.ApplyRequirements(R19) (colliders toggled in ascending Id)
        public SwitchTargetProviderCommand(ITargetProvider provider, Action applyRequirements);
    }

    // PendingCommandQueue (IMP-LOOP): ★ public void Enqueue(in SwitchTargetProviderCommand command);
    //   Begin order 0: slot.Replace(command.Provider) -> command.ApplyRequirements(). Touches no Strategies type.
    //   (rev 15, implemented) wraps PendingCommand.SwitchTargetProvider(command); the queue's full API (ctor
    //   (TargetProviderSlot, GameDataRegistry, SimulationRules), owner-kind RegisterHandler, Clear) is in 5.15.
    //   SwitchTargetProviderCommand ctor: null provider or callback -> ArgumentNullException.
    // TargetProviderSlot (IMP-LOOP): ★ public void Replace(ITargetProvider next);   // Begin (this command) and RunSession.Reset(in RunStrategies) only; throws if StepActive && phase != Begin
    //   (rev 15, implemented) ctor TargetProviderSlot(IStepClockReader clock); Current (null when empty); Kind throws when empty;
    //   Replace(null) empties the slot, the same instance is a no-op, a switch logs "[Loop] Target provider switched to <Kind>.";
    //   TryFindNearest returns false when empty. Still not an IStepPhaseHandler (5.0.1).
}
```
- (11회차) 명령을 만드는 쪽은 App이다: 개발자 모드는 `IDevModeHost.RequestTargetProviderSwitch(kind)`(★, 5.15)를 부르고, `GameBootstrap`이 `StrategyFactory`로 새 공급자를 만들어 위 명령을 `PendingCommandQueue`에 넣는다. 콜백 안의 `Required` 재계산·`ApplyRequirements`는 App 코드이므로 Simulation → Strategies 참조가 생기지 않는다(5c.1).
- (14회차, 기준선 명문화 — App/LOOP 계약) **B(`SpatialHashTargetProvider`)를 쓰려면 `MonsterSpatialIndex.Required = true`가 전제다.** `Required = false`인 채 B를 쓰면 인덱스가 BuildIndex에서 갱신되지 않아 결과가 오래되고, 스냅샷이 줄어든 뒤에는 오래된 인덱스가 범위 밖 스냅샷 인덱스를 가리켜 인덱서 예외가 나므로 `TryFindNearest`의 "절대 던지지 않는다"가 깨질 수 있다. 코드에는 이 경우를 막는 가드가 없다. 그래서 판 시작 콜백과 위 `ApplyRequirements` 콜백(App)은 B를 고를 때(또는 R19가 자체 충돌 등으로 인덱스를 요구할 때) 반드시 `Required`를 켠다(5c.3 #9 BuildIndex 행).
- (4회차) `TargetProviderSlot`은 `ITargetProvider`만 구현하며 `IStepPhaseHandler`가 아니다. BuildIndex 단계의 핸들러(order 0·5·10)가 모두 끝난 직후 `SimulationDriverMid`가 `TargetProviderSlot.OnSnapshotBuilt(snapshot)`을 **직접 호출**한다(5c.3 #9 BuildIndex 행). 그래서 공급자는 항상 확정된 스냅샷·재구축된 공간 해시를 받는다.
- 큰 몬스터는 해시에 들어가지 않고, `QueryCircle`·고리 탐색 뒤에 항상 별도로 전수 검사한다(SPEC F16, R25).
- (13회차) 공간 해시 셀 크기 기본값 2.0의 단일 소유자는 Core `StrategySelection.DefaultSpatialHashCellSize`(5.15)다. Strategies의 `SpatialHashSettings.CellSize` 기본값(TAC-F16-4)은 이 상수를 참조하고 2.0을 다시 쓰지 않는다(Core는 Strategies를 참조할 수 없으므로 방향은 Strategies → Core). 13회차 시점 코드는 `private const float DefaultSpatialHashCellSize = 2f`다 — **13회차: public const로 공개 — 웨이브 2 IMP-SPATIAL 착수 전 IMP-CORE가 반영**. (14회차) 반영 확인됨: main d06b0bb에서 `public const float DefaultSpatialHashCellSize = 2f`이고 `SpatialHashSettings`의 필드 초기값이 이를 참조한다.

#### 5.7.1 구현 확정 의미 (14회차, 웨이브 2a IMP-SPATIAL A·B, main d06b0bb)

- **`QueryCircle(center, radius, List<int> results)`**: 출력 목록을 **비운 뒤** 채운다(덧붙이지 않음). 셀 범위를 `radius + MaxHashedRadius`로 넓힌 정사각형의 셀에 든 해시 항목 전부(**상위 집합**, 정확한 원-원 겹침 판정 없음)에 모든 `IsLarge` 항목을 더해 **스냅샷 인덱스 오름차순**(= `EntityHandle` 오름차순)으로 돌려준다. 그러므로 **소비자(5.9 `SelfCollisionStrategy` 등)는 반드시 정확 거리 판정을 다시 한다.** `results == null`이면 `ArgumentNullException`. 음수·NaN `radius`에서는 해시 항목 없이 큰 몬스터만 돌아간다(`QueryCells`가 빈 결과).
- **`ForEachRing(point, ring, List<int>)`**: 역시 비운 뒤 채운다. 질의점 셀에서 체비쇼프 셀 거리가 **정확히 ring**인 셀만(ring 0 = 자기 셀), 점유 셀 범위로 잘라서 보며, 큰 몬스터는 넣지 않는다. 음수 ring은 `ArgumentOutOfRangeException`, null 목록은 `ArgumentNullException`.
- **`MonsterSpatialIndex.CellCounts`**: 재구축·`Clear` 뒤 처음 읽을 때 셀별 개수를 계산하고 다음 재구축까지 캐시한다(개발자 시각화 전용, 큰 몬스터 미포함).
- **B `OnSnapshotBuilt`**: [기본값]으로 명문화 — 인덱스가 읽는 버퍼와 다른 `MonsterSnapshotBuffer`가 오면 `ArgumentException`을 던진다(계약 밖 추가 검사, 조립 오류를 일찍 드러낸다). `OnSnapshotBuilt(null)`은 예외 없이 참조를 잊는다(A도 같다).
- **`TryFindNearest`**(A·B): 스냅샷을 받기 전이거나 몬스터 0기이면 false, 던지지 않는다. B는 해시 항목이 있을 때만 고리 탐색을 하고(첫 고리 = `FirstOccupiedRing`, TAC-F16-2 각주의 여유 있는 종료 조건), 그 뒤 큰 몬스터를 전수 검사한다. 두 구현 모두 `ProfilerMarkers.Targeting`으로 감싸고, 선택은 `TargetOrdering.IsBetter`(R6)다.
- **`SpatialHash`**: 셀 키는 R14 그대로(`CellCoordinate = Mathf.FloorToInt(value / cellSize)`, internal). 점유 셀의 최소·최대 셀 좌표를 삽입 때 갱신해 `QueryCells`·고리 탐색이 점유 범위 밖 빈 셀을 돌지 않게 한다. 셀 목록은 `Clear` 때 재사용 풀로 돌아간다.
- (14회차, 각주) 셀 크기 0.5·성긴 배치·무리 밖 질의점에서는 B가 빈 셀을 많이 순회해 동등성 테스트 10,000배치가 약 10초 걸렸다. 실제 게임 분포(질의점 = 플레이어, 무리 반경 45 안 밀집)와 달라 측정 곡선에 주는 영향은 미확인이다. `|x / cellSize| > 2^31`인 좌표의 셀 좌표 오버플로는 처리하지 않는다 — 월드 범위 밖이므로 [기본값] 허용.
