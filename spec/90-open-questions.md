## 4. 미확정 사항 (Open Questions)

PRD의 29건과 이전 개정의 Q1~Q43 중 해소된 항목은 이 목록에서 제거했다 (4회차 개정에서 Q40·Q41이 확정·반영되어 제거되었다). Q8, Q9, Q12, Q13, Q42, Q43, Q44, Q46은 PM 기본값(TECH_SPEC 참조)을 본문에 반영하고 "기본값 채택"으로 표시했다 — 구현·밸런싱 중 바꿀 수 있다. **미확정으로 남은 것은 Q1·Q38·Q39·Q45(4건, 모두 구현 단계 조정)뿐**이며 모두 구현 단계에서 정해도 되는 항목이다. 표시 기준: **[구현 단계 조정]** 은 구현·밸런싱·실측 단계에서 정해도 되는 항목이다. **blocking인 항목은 없다** (기능 경계를 추측해서 나눈 곳은 없음).

**미확정 (구현 단계 조정)**
- Q1. [구현 단계 조정] 플레이어 체력·이동속도 등 기본 스탯, 무기 피해량·쿨다운·단계별 증가량, 몬스터 체력·속도·접촉 피해, 경험치 곡선, 선택지 가중치, W2/W3 피해 틱 간격, 플레이어 공통 무적 시간 등 수치는 구현·밸런싱 단계에서 정하고 JSON으로 노출하는 것으로 해도 됩니까? (메모: 보스전에 시간 제한이 없으므로 플레이어가 보스를 못 잡으면 판이 끝나지 않을 수 있다 — 보스 체력·플레이어 화력 밸런싱 시 확인.)
- Q38. [구현 단계 조정] 레벨업 회복 선택지 가중치 `w_회복 = w_base × (1 - r)²`의 `w_base`(기본 가중치) 값은 얼마입니까? 다른 선택지 가중치와의 상대 크기로 정해야 하므로 밸런싱 시 확정합니다. (선택지 풀 파일이 없는 폴백 상황에서는 `w_base`를 다른 후보와 같은 기준 가중치로 둔다고 해석했습니다. 이 해석이 맞는지도 함께 확정합니다.)
- Q39. [구현 단계 조정] Unity 2D `Rigidbody2D`의 Collision Detection 기본값이 `Discrete`인지 구현 단계에서 실측 확인이 필요합니다. F18의 E2 테스트와 비교 실험 조건("양쪽 모두 CCD 끔")의 전제입니다.
- Q45. [구현 단계 조정] 측정 목표치 확정: F10의 목표치(합격선) 숫자는 **F19 완료 후 A0 기준선 측정 시점**에 확정하고 그때 이 SPEC을 개정한다. (기존에는 "F9 직후"로 적혀 있었으나, 측정이 개발자 모드 위에서만 가능하므로 F19 완료 후로 바로잡았다.)

**기본값 채택 (TECH_SPEC 참조, 구현·밸런싱 시 변경 가능)**
- Q8. 기본값 채택: W3 장판의 생성 위치는 **가장 가까운 적의 위치**다. (F6 본문에 반영.)
- Q9. 기본값 채택: W1·W4 투사체는 **수명이 만료되면 소멸**하고 **사거리 제한은 없다**(수명으로 대체). W4는 대상이 없으면 마지막 진행 방향으로 직진한다. (F6 본문에 반영.)
- Q12. 기본값 채택: 첫 실행(기록 없음)의 최고 기록은 **"-"** 로 표시한다. 클리어 시 생존 시간은 10분이 아니라 **보스 처치까지의 실제(게임) 시간**으로 기록한다. 최고 기록은 **사망/클리어와 무관하게** 갱신 대상이다. (F8 본문에 반영.)
- Q13. 기본값 채택: 풀은 **상한을 넘는 요청이 오면 확장**한다. 사전 생성 개수·최대 크기의 구체 값은 측정 후 정한다. (F9 본문에 반영.)
- Q42. 기본값 채택: 진화 조건을 충족한 무기가 2개일 때 **무기 슬롯 순서(슬롯 번호가 작은 쪽)** 로 먼저 진화시킨다. (F7 본문에 반영.)
- Q43. 기본값 채택: JSON 핫 리로드 시 **다음 스폰과 다음 레벨업 선택지부터 새 정의를 적용**하고, 이미 활성 상태인 객체는 유지한다. (F19 본문에 반영.)
- Q44. 기본값 채택: 카메라 **orthographic size 9**(월드 단위)를 채택한다. 16:9에서 화면 반대각의 절반은 √(9²+16²) ≈ **18.36 < 스폰 반경 20**이어서 **여유가 1.64**다. 카메라는 플레이어에 즉시 스냅하므로(F1) 이 여유가 보존된다. 카메라를 줌하면 r=20과 D=45를 함께 재검토해야 한다. (F3 본문에 반영.)
- Q46. 기본값 채택: 4회차 개정 중 발견한 작은 공백 5건을 PM 기본값으로 확정했다. ① 작업 영역이 1280x720보다 작은 모니터는 **1280x720 창으로 열고 잘림을 허용**하며, F13 테스터 배포 README의 최소 요구사항에 "1280x720 이상 작업 영역"을 명시한다. (F8 요구사항·수용 기준, F13 수용 기준에 반영.) ② W3 장판은 생성 대상(적)이 없으면 **장판을 생성하지 않고 쿨다운도 소비하지 않으며 다음 스텝에 다시 시도**한다(W1 규칙과 동일). (9회차: `placement: nearestEnemy` 장판에 한함, `player` 장판은 타깃 무관 — Q47 ③ 번복 참조) (F6 W3 수용 기준에 반영.) ③ F10 항목 6(메모리)은 **측정 구간의 평균과 최댓값을 CSV에 두 열로 기록**한다. (F10 표·수용 기준, F19 CSV 수용 기준에 반영.) ④ 플레이어 공통 무적 시간 필드는 **초 단위로 입력하고 로드 시 스텝으로 환산**하며 W2/W3 틱 간격과 같은 "초→스텝 환산" 공유 규칙을 쓴다. (F11 수용 기준에 반영.) ⑤ 레벨업 화면에서 ESC로 일시정지한 뒤 재개하면 **선택지 3개를 그대로 유지**한다. (F5·F8 수용 기준에 반영.)
- Q47. 기본값 채택(7회차): 무기 절 규정 8건 — ① 첫 보유 뒤 첫 발사는 쿨다운 대기 없음 ② 진화 결과 무기의 첫 동작은 교체 다음 스텝 즉시, 궤도 원 공백 1스텝 ③ W3 `placement: player`도 타깃 없으면 재시도(**9회차 번복**: 대상이 필요 없으므로 적이 없어도 생성·쿨다운 소비, 사용자 결정) ④ W4 첫 발사 방향은 W1 규칙 ⑤ 보유 항목의 새 획득 후보 제외 ⑥ E2·W2~W4 2~5단계 예시값은 TECH 5.13(Q1 대상) ⑦ P1은 E1·E2에도 적용 ⑧ P1 범위는 쿨다운(발사·생성 간격)만(사용자 확정). (F2·F5·F6·F7 본문에 반영.)
- Q48. 기본값 채택(8회차): 8회차 기본값 채택 항목 요지(F19 8회차 신규 4건·F02 P1 적용 시점·F04 상자 2개·F08 강제 종료·F07 소비된 원본 무기 재획득 불가·F03/F10 보완 — 시간 점프 앞으로만 / 조기 보스 처치 클리어·재등장 없음 / 공격 끔 범위 / 핫 리로드 스냅샷 / P1 적용 시점 / 상자 2개 순차 / 강제 종료 미저장 / 상한의 보스 제외·소환 규칙 / 측정 무효 조건). (F2·F3·F4·F8·F10·F19 본문에 반영.)
- Q49. 기본값 채택(11회차): 11회차 사용자 결정(몬스터 체력의 스폰 구간별 배율, HUD 보유 무기·패시브 레벨 텍스트 패널, 개발자 오버레이 현황 패널, 오버레이 영어 레이블·OS 폰트)을 옮기며 PM 기본값으로 닫은 공백 — ① 보스(M4)와 보스 소환 몬스터는 체력 배율을 적용하지 않는다 ② 배율을 곱한 체력은 반올림하지 않는다 ③ HUD의 배율 표시는 소수점 1자리 ④ HUD 텍스트 패널 위치는 화면 왼쪽 아래 ⑤ 아이콘 슬롯 바(무기 4 + 패시브 3, 색 아이콘 + 레벨 숫자)는 1차 MVP 범위 밖의 나중 후보이며, 무기 아이콘 키·레지스트리 확장이 선행 조건이다 ⑥ 구간의 체력 배율 값이 양의 유한 실수가 아니면 그 구간의 배율만 1.0으로 대체하고 경고를 남긴다(정의 단위 정책의 필드 적용 — 구간과 스폰 테이블은 유효, 플레이 불가 ④ 아님) ⑦ 배율은 스폰 경로가 아니라 스폰된 스텝이 속한 구간으로만 정해지므로 개발자 모드 스폰(즉시 N기 생성·특정 종만 스폰·N 유지 재스폰·시간 점프 뒤 스폰)에도 적용되고, 제외는 보스와 보스 소환분뿐이다. 측정 CSV 헤더에 구간별 배율 목록을 기록한다 ⑧ 스폰 구간은 시작 포함·끝 제외(`[시작, 끝)`)이고, 구간 밖 스텝(10분 이후, 구간 사이 빈틈)은 현재 스텝 이하에서 시작한 가장 최근 구간의 배율을 유지한다(시작한 구간이 없으면 1.0). HUD와 현황 패널도 같은 값을 표시하며 줄을 숨기지 않는다. (F3·F8·F11·F19 본문에 반영.)
