### F19. 개발자 모드 (측정·디버그 하네스)

**요구사항**: 별도 씬을 만들지 않고 **실제 게임 씬에서 제어**하는 개발자 모드다. **릴리스 빌드에도 포함**되며(Q40 확정), **커맨드라인 인자 `--dev`로 활성화**하고, 활성화된 상태에서 **F1 키로 오버레이를 토글**한다. **비활성 상태에서는 시작 시 인자 확인 1회 외에 어떤 분기도, 키 감시도 없다.** 근거: ① 실제 게임과 같은 코드 경로에서 측정하므로 "측정 환경이 실제와 다르다"는 의심이 없다. ② 무적·스폰 중단·무기 즉시 설정은 개발 중 디버깅·밸런싱에 계속 쓰이므로 측정 전용 투자가 아니다. ③ 배포 빌드 하나로 플레이·측정·JSON 핫 리로드 시연을 모두 할 수 있다. F10의 모든 측정은 이 모드에서 수행한다. 모든 기능은 고정 스텝(3.0 F) 위에서 동작한다. 모든 시뮬레이션 객체의 ID는 "인덱스 + 세대" 형식이다(3.0 H).

**필수 기능: 결정론 (측정의 전제)**
- 레벨업 비활성 (전개 분기의 유일한 원인 제거)
- 고정 시드 설정
- **플레이어 자동 경로** (반지름·속도 지정, 원형 순회). "무적 + 정지"로 두면 안 된다. 적이 플레이어를 추적해 한 지점에 전부 쌓여 격자 한 셀에 수백 개가 들어가고 공간 분할이 비현실적으로 최악으로 나오며, 적이 도달한 뒤엔 움직이지 않아 격자 재배치 부하가 0이 되기 때문이다.
- 전략 토글 4개 (F9, F16, F17, F18). 타깃 탐색(F16)은 즉시, 나머지는 다음 판 시작 시 적용(3.0 B).
- 통계 수집·표시·**CSV 내보내기**
- **충돌 이벤트 로그 기록·내보내기** (E1·E2 동등성 테스트용). 형식은 (스텝 번호, 종류(Enter/Exit), 채널, 객체 ID 쌍).
- 고정 스텝 N스텝 후 자동 종료 + 결과 출력 (배치 측정용)

**플레이 제어**: 무적(플레이어 피격 면제) / 무기 구성 즉시 설정(W1~W4, 단계 지정) / 공격 on/off

**적 제어**: 스폰 중단 / **즉시 N기 생성** / 특정 종만 스폰 / 적 수 N 유지 모드(죽으면 재스폰, 풀링 부하 발생) / **디스폰 거리 D 설정** (N을 올릴 때 D도 올려 밀도를 일정하게 유지: N ≤ 400이면 45, 초과면 `45·√(N/400)`, F10)

**시각화 (1순위)**: **공간 해시 격자 표시**(셀 경계 + 셀별 객체 수) / 충돌 반경 표시 / **타깃 탐색 결과 표시**(각 무기가 고른 타깃까지 선, 결정론·타이브레이크 확인에 직접 사용) / 스폰 반경·디스폰 반경 원 표시

**시간 제어**: 시간 배속 0.25x~**3x** (측정 중에는 끈다. 상한 3x는 catch-up 상한 3스텝과 일치시킨 값이며, 오버레이에 **실제 배속**을 표시한다) / 게임 시간 즉시 점프 (보스 구간 테스트) / 한 스텝씩 진행(step-through)

**상태 조작**: **체력 설정** (F5의 `(1-r)²` 곡선 확인에 직접 필요) / 경험치 즉시 획득 / 레벨 즉시 상승 / 보스 즉시 소환 / 상자 즉시 스폰 (진화 확인)

**데이터**: **JSON 핫 리로드**(재시작 없이, F11 시연에 직접 사용) / 로드된 데이터 + 검증 결과 덤프

**제외**: 콘솔 명령어 파서(토글 UI로 충분), 리플레이 저장·재생(고정 시드 + 결정론으로 시드만으로 재현되므로 중복), 자체 프로파일러(Unity Profiler 사용).

**수용 기준**
- *설계 제약*: 주어진 개발자 도구는 게임 로직에 `if (devMode)` 분기를 흩뿌리지 않아야 한다. 최소 수정 원칙(`CODING_GUIDE.md` §1)이 무너지고 측정 시 그 분기 비용이 수치에 섞이기 때문이다. 별도 컴포넌트·오버레이로 두고 게임 코드는 값을 주입받는 형태여야 한다 (예: 플레이어 자동 경로는 입력 소스 교체 `IInputSource`, F1). F16~F18의 전략 교체와 같은 구조다.
- (4회차 수정) 주어진 개발자 모드가 꺼져 있을 때(`--dev` 인자 없음) 일반 플레이 흐름(타이틀 → 플레이 → 결과)과 게임 로직 동작이 개발자 모드 코드가 없는 것과 동일해야 한다. **단 시작 시 커맨드라인 인자 확인 1회의 분기는 예외**이며, 그 외에 비활성 상태에서 실행되는 분기·감시(키 입력 폴링 등)가 없어야 한다.
- 주어진 개발자 모드가 켜진 실제 게임 씬에서 레벨업 비활성, 고정 시드, 플레이어 자동 경로가 설정되면, 같은 시드와 같은 설정으로 N스텝 실행했을 때 몬스터 수와 위치가 매번 동일해야 한다.
- 주어진 플레이어 자동 경로는 반지름과 속도를 지정할 수 있어야 하며 원형으로 순회해야 한다. 플레이어가 정지한 채 무적인 상태만으로는 측정 구성을 대체할 수 없다.
- 주어진 전략 토글 4개를 서로 독립적으로 전환할 수 있어야 하며, F10 묶음 A의 6회 구성과 묶음 B(전수 순회/공간 해시)·묶음 C(엔진 대안, 나머지 세 전략은 기준선) 구성을 모두 설정할 수 있어야 한다.
- 주어진 적 수 N을 50/100/200/400으로 설정(적 수 N 유지 모드)할 수 있어야 하고, 400기 동시 존재 상한을 해제하면 그 이상으로도 설정할 수 있어야 한다 (한계 측정용, A0 탐색).
- (4회차 수정) 주어진 N을 올릴 때 디스폰 거리 D를 설정할 수 있어야 하며, N ≤ 400이면 45, N > 400이면 `45·√(N/400)`로 설정할 수 있어야 한다.
- 주어진 적 수 N 유지 모드에서 적이 죽으면 재스폰되어 풀의 생성·반납 부하가 발생해야 한다.
- 주어진 스폰 중단, 즉시 N기 생성, 특정 종만 스폰이 동작해야 한다.
- 주어진 무적이 켜지면 플레이어가 피격 피해를 받지 않아야 하고, 공격 on/off와 무기 구성(W1~W4, 단계 지정) 즉시 설정이 동작해야 한다.
- (4회차 수정) 주어진 통계 수집은 F10 **6개 항목**(평균 FPS, 1% low 또는 최악 프레임 시간, 프레임당 GC 할당, 동시 몬스터 수, 시스템 ms의 스텝당·프레임당 값, 메모리의 구간 평균·최댓값)을 얻는 데 필요한 값을 모두 제공해야 하고, **활성 젬 수**도 함께 제공해야 하며, **CSV로 내보낼 수 있어야** 한다.
- (4회차 수정) 주어진 충돌 이벤트 로그를 기록하고 파일로 내보낼 수 있어야 하며, E1·E2 비교에 쓸 수 있는 형태 **(스텝 번호, 종류(Enter/Exit), 채널, 객체 ID 쌍)** 여야 한다. 객체 ID는 "인덱스 + 세대" 형식이다.
- 주어진 고정 스텝 N스텝 후 자동 종료를 설정하면 정확히 N스텝 실행 후 결과를 출력하고 종료해야 한다.
- 주어진 시각화(공간 해시 격자 + 셀별 객체 수, 충돌 반경, 타깃 탐색 결과 선, 스폰·디스폰 반경 원)가 각각 켜고 끌 수 있어야 하며, 꺼져 있으면 렌더링·로직 비용이 발생하지 않아야 한다.
- (4회차 수정) 주어진 시간 배속 0.25x~**3x**, 게임 시간 즉시 점프, 한 스텝 진행(step-through)이 동작해야 한다. 시간 배속은 스텝 간격(1/60초)을 바꾸지 않아야 하며 결정론을 깨지 않아야 한다. 오버레이에 실제 배속이 표시되어야 한다.
- 주어진 체력 설정, 경험치 즉시 획득, 레벨 즉시 상승, 보스 즉시 소환, 상자 즉시 스폰이 동작해야 한다.
- (4회차 수정) 주어진 JSON 핫 리로드를 실행하면 재시작 없이 변경된 JSON이 반영되고, 로드된 데이터와 검증 결과 덤프를 확인할 수 있어야 한다. 이미 활성 상태인 객체(몬스터, 보유 무기)는 유지되고, 새 정의는 **다음 스폰과 다음 레벨업 선택지부터** 적용되어야 한다(Q43, 기본값 채택).
- 주어진 catch-up 상한에 걸려 슬로모션이 발생해도 측정이 가능해야 하며, 스텝당 시간 수집은 슬로모션의 영향을 받지 않아야 한다.
- 주어진 개발자 모드에는 콘솔 명령어 파서, 리플레이 저장·재생, 자체 프로파일러가 존재하지 않아야 한다.
- 주어진 개발자 모드를 Development Build에서 사용하고 Profiler를 연결할 수 있어야 한다.
- (5회차 수정) 주어진 **개발자 모드 오버헤드 비교**: 인자 없이 실행한 릴리스 빌드와 개발자 모드 코드를 제거한 빌드(`SURVIVOR_NO_DEV` 심볼)를 같은 일반 플레이 절차(같은 시드는 불가하므로 같은 시간·같은 조작 스크립트 없이 3분 플레이 3회)로 Profiler 측정해, 평균 프레임 시간과 프레임당 GC 할당의 차이가 측정 노이즈 범위 안이어야 한다. 이 비교는 F10 16회 측정과 별도의 1회이며 결과는 devlog에 기록한다(F14 "채택하지 않은 대안"의 Development Build 전용안과 짝). "`--dev` 활성 + F1 미입력" 상태는 비교 대상이 아니다.
- (4회차 신규) 주어진 개발자 모드가 활성화된 상태에서만 F1 키로 오버레이가 토글되어야 한다. 비활성 상태에서는 F1 키 입력을 감시하지 않아야 한다.
- (5회차 수정) 주어진 오버레이 안의 **측정 시작**을 누르면 나머지 조건(시각화 전부 끔, 충돌 이벤트 로그 끔, 배속 1x, 한 스텝 모드 아님, 상자 드랍 0%, 프리셋 무기 구성 고정)을 검사해 하나라도 어긋나면 **거부**하고 원인을 표시해야 한다. 통과하면 오버레이를 **자동으로 숨기고** 측정을 시작해야 하며, 측정 중 오버레이를 다시 열면 **그 세션은 무효로 표시**되어야 한다(F10 측정 시작 규칙).
- (4회차 신규) 주어진 측정에서 적 수가 N에 도달한 뒤 300스텝은 통계 집계에서 제외되어야 한다.
- (4회차 신규) 주어진 개발자 모드로 측정 중일 때는 `runInBackground`가 켜지고 창 포커스를 잃어도 자동 일시정지가 일어나지 않아야 한다(F8).
- (4회차 수정) 주어진 측정 CSV 헤더에는 전략 조합, 적 수 N, 디스폰 거리 D, 시드, 공간 해시 셀 크기, 측정 길이, 스텝 간격, 무적 여부, 고정 무기 구성(W1~W4 단계), 스폰 중단 + N 유지 모드 여부, 수직동기·`targetFrameRate`·스크립팅 백엔드·점진적 GC 설정, 제외한 워밍업 스텝 수, PC 사양(CPU, GPU, RAM, OS)이 기록되어야 하고, 본문 열에는 F10 6개 항목과 활성 젬 수가 들어가야 한다. **메모리는 측정 구간의 평균과 최댓값 두 열**이다(Q46, 기본값 채택). 파일은 UTF-8 BOM, 소수점은 InvariantCulture 형식이다(F11).
- (4회차 신규) 주어진 개발자 모드 사용법(활성화 `--dev`, F1 토글, 측정 절차)이 `README.md`의 전용 절에 문서화되어야 한다(F14 매핑 표).
