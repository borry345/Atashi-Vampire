### F19. 개발자 모드 (측정·디버그 하네스)

**요구사항**: 별도 씬을 만들지 않고 **실제 게임 씬에서 제어**하는 개발자 모드다. **릴리스 빌드에도 포함**되며(Q40 확정), **커맨드라인 인자 `--dev`로 활성화**하고, 활성화된 상태에서 **F1 키로 오버레이를 토글**한다. **비활성 상태에서는 시작 시 인자 확인 1회 외에 어떤 분기도, 키 감시도 없다.** 근거: ① 실제 게임과 같은 코드 경로에서 측정하므로 "측정 환경이 실제와 다르다"는 의심이 없다. ② 무적·스폰 중단·무기 즉시 설정은 개발 중 디버깅·밸런싱에 계속 쓰이므로 측정 전용 투자가 아니다. ③ 배포 빌드 하나로 플레이·측정·JSON 핫 리로드 시연을 모두 할 수 있다. F10의 모든 측정은 이 모드에서 수행한다. 모든 기능은 고정 스텝(3.0 F) 위에서 동작한다. 모든 시뮬레이션 객체의 ID는 "인덱스 + 세대" 형식이다(3.0 H).

**필수 기능: 결정론 (측정의 전제)**
- 레벨업 비활성 (전개 분기의 유일한 원인 제거)
- 고정 시드 설정
- **플레이어 자동 경로** (반지름·속도 지정, 원형 순회). "무적 + 정지"로 두면 안 된다. 적이 플레이어를 추적해 한 지점에 전부 쌓여 격자 한 셀에 수백 개가 들어가고 공간 분할이 비현실적으로 최악으로 나오며, 적이 도달한 뒤엔 움직이지 않아 격자 재배치 부하가 0이 되기 때문이다.
- 전략 토글 4개 (F9, F16, F17, F18). 타깃 탐색(F16)은 즉시, 나머지는 다음 판 시작 시 적용(3.0 B).
- 통계 수집·표시·**CSV 내보내기**
- **충돌 이벤트 로그 기록·내보내기** (E1·E2 동등성 테스트용). 형식은 (스텝 번호, 종류(Enter/Exit), 채널, 객체 ID 쌍).
- 고정 스텝 N스텝 후 자동 종료 + 결과 출력 (배치 측정용)

**플레이 제어**: 무적(플레이어 피격 면제) / 무기 구성 즉시 설정(W1~W4, 단계 0~5 지정, 0 = 미보유, 12회차 수정) / (12회차 신규) 패시브 구성 즉시 설정(P1~P3, 단계 0~최대 지정, 0 = 미보유) / 공격 on/off

**적 제어**: 스폰 중단(12회차 보강: 일반 스폰 켜기/끄기 토글, 판 진행 중 다음 스텝부터 즉시 적용) / **즉시 N기 생성** / 특정 종만 스폰 / 적 수 N 유지 모드(죽으면 재스폰, 풀링 부하 발생) / **디스폰 거리 D 설정** (N을 올릴 때 D도 올려 밀도를 일정하게 유지: N ≤ 400이면 45, 초과면 `45·√(N/400)`, F10)

**시각화 (1순위)**: **공간 해시 격자 표시**(셀 경계 + 셀별 객체 수) / 충돌 반경 표시(12회차 보강: 판정 반지름 — 표시 배율 1.25를 적용하지 않은 값, 00-common 3.0 C 표시 크기) / **타깃 탐색 결과 표시**(각 무기가 고른 타깃까지 선, 결정론·타이브레이크 확인에 직접 사용. 12회차 보강: 정의 데이터의 동작이 유도(매 스텝 재추적)인 투사체(현재 W4)가 현재 추적 중인 타깃까지의 선 포함) / 스폰 반경·디스폰 반경 원 표시

**시간 제어**: 시간 배속 0.25x~**3x** (측정 중에는 끈다. 상한 3x는 catch-up 상한 3스텝과 일치시킨 값이며, 오버레이에 **실제 배속**을 표시한다) / 게임 시간 즉시 점프 (보스 구간 테스트) / 한 스텝씩 진행(step-through)

**상태 조작**: **체력 설정** (F5의 `(1-r)²` 곡선 확인에 직접 필요) / 경험치 즉시 획득 / 레벨 즉시 상승 / 보스 즉시 소환 / 상자 즉시 스폰 (진화 확인)

**데이터**: **JSON 핫 리로드**(재시작 없이, F11 시연에 직접 사용) / 로드된 데이터 + 검증 결과 덤프

**(11회차 신규) 현황 패널**: 동작·버그 확인용 읽기 전용 표시 — 보유 무기·패시브와 레벨(진화 무기는 `(evolved)` 표기 — 영어 레이블 원칙, 12회차 수정) / 현재 스폰 구간의 몬스터 체력 배율 / 게임 시간과 스텝 번호 / 판 시드 / 생존 몬스터 수(보스 포함) / 활성 젬 수 / 현재 전략 조합 4종(F9·F16·F17·F18) / 실제 배속(시간 제어의 "실제 배속 표시"는 이 항목으로 통합한다). 오버레이 레이블은 영어이고, 폰트는 OS 폰트 "Malgun Gothic"(없으면 엔진 기본 폰트, 폰트 자산 추가 없음)이다.

**(12회차 신규) 카메라 줌**: 카메라 orthographic size를 기본 9에서 4.5~27 범위로 조정하고 9로 되돌리는 리셋을 둔다. 표시 전용이며 스폰 반경·디스폰 거리·공간 해시 격자·판정은 월드 단위라 바뀌지 않는다. 줌 아웃 중 스폰이 화면 안에 보이는 것은 허용한다(F03 "스폰 지점은 화면 밖" 기준의 예외). 개발자 모드가 아니면 항상 9다. 측정 시작이 통과되면 9로 자동 복귀한다.

**(12회차 신규) 커맨드 로그**: 오버레이의 마지막 명령 결과 한 줄(예: "Level up queued."가 뜨던 자리)을 최근 명령 로그 여러 줄로 넓힌다. 최신 줄이 위, 최대 10줄, 각 줄은 판 번호 + 스텝 번호 + 명령 이름 + 결과(수행/거부 사유)다. 상자 효과 결과(F04 12회차 "최근 상자 결과 목록")도 같은 로그에 스텝 순으로 섞어 표시하며, 같은 스텝이면 명령이 먼저다. 새 판 시작 시 지우지 않고 세션 동안 유지하며 파일로 내보내지 않는다(충돌 이벤트 로그·측정 CSV와 별개).

**제외**: 콘솔 명령어 파서(토글 UI로 충분), 리플레이 저장·재생(고정 시드 + 결정론으로 시드만으로 재현되므로 중복), 자체 프로파일러(Unity Profiler 사용).

**수용 기준**
- *설계 제약*: 주어진 개발자 도구는 게임 로직에 `if (devMode)` 분기를 흩뿌리지 않아야 한다. 최소 수정 원칙(`CODING_GUIDE.md` §1)이 무너지고 측정 시 그 분기 비용이 수치에 섞이기 때문이다. 별도 컴포넌트·오버레이로 두고 게임 코드는 값을 주입받는 형태여야 한다 (예: 플레이어 자동 경로는 입력 소스 교체 `IInputSource`, F1). F16~F18의 전략 교체와 같은 구조다.
- (4회차 수정) 주어진 개발자 모드가 꺼져 있을 때(`--dev` 인자 없음) 일반 플레이 흐름(타이틀 → 플레이 → 결과)과 게임 로직 동작이 개발자 모드 코드가 없는 것과 동일해야 한다. **단 시작 시 커맨드라인 인자 확인 1회의 분기는 예외**이며, 그 외에 비활성 상태에서 실행되는 분기·감시(키 입력 폴링 등)가 없어야 한다.
- 주어진 개발자 모드가 켜진 실제 게임 씬에서 레벨업 비활성, 고정 시드, 플레이어 자동 경로가 설정되면, 같은 시드와 같은 설정으로 N스텝 실행했을 때 몬스터 수와 위치가 매번 동일해야 한다.
- 주어진 플레이어 자동 경로는 반지름과 속도를 지정할 수 있어야 하며 원형으로 순회해야 한다. 플레이어가 정지한 채 무적인 상태만으로는 측정 구성을 대체할 수 없다.
- 주어진 전략 토글 4개를 서로 독립적으로 전환할 수 있어야 하며, F10 묶음 A의 6회 구성과 묶음 B(전수 순회/공간 해시)·묶음 C(엔진 대안, 나머지 세 전략은 기준선) 구성을 모두 설정할 수 있어야 한다.
- 주어진 적 수 N을 50/100/200/400으로 설정(적 수 N 유지 모드)할 수 있어야 하고, 400기 동시 존재 상한을 해제하면 그 이상으로도 설정할 수 있어야 한다 (한계 측정용, A0 탐색).
- (4회차 수정) 주어진 N을 올릴 때 디스폰 거리 D를 설정할 수 있어야 하며, N ≤ 400이면 45, N > 400이면 `45·√(N/400)`로 설정할 수 있어야 한다.
- 주어진 적 수 N 유지 모드에서 적이 죽으면 재스폰되어 풀의 생성·반납 부하가 발생해야 한다.
- 주어진 스폰 중단, 즉시 N기 생성, 특정 종만 스폰이 동작해야 한다.
- (12회차 수정) 주어진 무적이 켜지면 플레이어가 피격 피해를 받지 않아야 하고, 공격 on/off와 무기 구성(W1~W4, 단계 0~5 지정) 즉시 설정이 동작해야 한다.
- (4회차 수정) 주어진 통계 수집은 F10 **6개 항목**(평균 FPS, 1% low 또는 최악 프레임 시간, 프레임당 GC 할당, 동시 몬스터 수, 시스템 ms의 스텝당·프레임당 값, 메모리의 구간 평균·최댓값)을 얻는 데 필요한 값을 모두 제공해야 하고, **활성 젬 수**도 함께 제공해야 하며, **CSV로 내보낼 수 있어야** 한다.
- (4회차 수정) 주어진 충돌 이벤트 로그를 기록하고 파일로 내보낼 수 있어야 하며, E1·E2 비교에 쓸 수 있는 형태 **(스텝 번호, 종류(Enter/Exit), 채널, 객체 ID 쌍)** 여야 한다. 객체 ID는 "인덱스 + 세대" 형식이다.
- 주어진 고정 스텝 N스텝 후 자동 종료를 설정하면 정확히 N스텝 실행 후 결과를 출력하고 종료해야 한다.
- (12회차 보강) 주어진 시각화(공간 해시 격자 + 셀별 객체 수, 충돌 반경, 타깃 탐색 결과 선, 스폰·디스폰 반경 원)가 각각 켜고 끌 수 있어야 하며, 꺼져 있으면 렌더링·로직 비용이 발생하지 않아야 한다. 타깃 탐색 결과 선이 켜져 있으면 무기→발사 시점 타깃 선에 더해, 정의 데이터의 동작이 유도(매 스텝 재추적)인 투사체(현재 W4) 각각에서 그 투사체가 현재 추적 중인 타깃까지의 선이 표시되어야 한다(추적 중인 타깃이 없는 투사체는 선 없음). 충돌 반경 표시는 판정 반지름(표시 배율 1.25를 적용하지 않은 값, 00-common 3.0 C)으로 그려야 한다. 시각화는 시뮬레이션 상태(3.0 F 결정론 기준 항목)를 바꾸지 않아야 한다.
- (4회차 수정) 주어진 시간 배속 0.25x~**3x**, 게임 시간 즉시 점프, 한 스텝 진행(step-through)이 동작해야 한다. 시간 배속은 스텝 간격(1/60초)을 바꾸지 않아야 하며 결정론을 깨지 않아야 한다. 오버레이에 실제 배속이 표시되어야 한다.
- 주어진 체력 설정, 경험치 즉시 획득, 레벨 즉시 상승, 보스 즉시 소환, 상자 즉시 스폰이 동작해야 한다.
- (4회차 수정, 11회차 보강) 주어진 JSON 핫 리로드를 실행하면 재시작 없이 변경된 JSON이 반영되고, 로드된 데이터와 검증 결과 덤프를 확인할 수 있어야 한다. 이미 활성 상태인 객체(몬스터, 보유 무기)는 유지되고, 새 정의는 **다음 스폰과 다음 레벨업 선택지부터** 적용되어야 한다(Q43, 기본값 채택. 스폰 구간 체력 배율도 다음 스폰부터 적용되며 이미 살아 있는 몬스터의 체력은 바뀌지 않는다 — F3 11회차).
- 주어진 catch-up 상한에 걸려 슬로모션이 발생해도 측정이 가능해야 하며, 스텝당 시간 수집은 슬로모션의 영향을 받지 않아야 한다.
- 주어진 개발자 모드에는 콘솔 명령어 파서, 리플레이 저장·재생, 자체 프로파일러가 존재하지 않아야 한다.
- 주어진 개발자 모드를 Development Build에서 사용하고 Profiler를 연결할 수 있어야 한다.
- (5회차 수정) 주어진 **개발자 모드 오버헤드 비교**: 인자 없이 실행한 릴리스 빌드와 개발자 모드 코드를 제거한 빌드(`SURVIVOR_NO_DEV` 심볼)를 같은 일반 플레이 절차(같은 시드는 불가하므로 같은 시간·같은 조작 스크립트 없이 3분 플레이 3회)로 Profiler 측정해, 평균 프레임 시간과 프레임당 GC 할당의 차이가 측정 노이즈 범위 안이어야 한다. 이 비교는 F10 16회 측정과 별도의 1회이며 결과는 devlog에 기록한다(F14 "채택하지 않은 대안"의 Development Build 전용안과 짝). "`--dev` 활성 + F1 미입력" 상태는 비교 대상이 아니다.
- (4회차 신규) 주어진 개발자 모드가 활성화된 상태에서만 F1 키로 오버레이가 토글되어야 한다. 비활성 상태에서는 F1 키 입력을 감시하지 않아야 한다.
- (5회차 수정, 8회차 보강, 11회차 보강) 주어진 오버레이 안의 **측정 시작**을 누르면 나머지 조건(시각화 전부 끔, 충돌 이벤트 로그 끔, 배속 1x, 한 스텝 모드 아님, 상자 드랍 0%, 프리셋 무기 구성 고정)을 검사해 하나라도 어긋나면 **거부**하고 원인을 표시해야 한다. 통과하면 오버레이를 **자동으로 숨기고** 측정을 시작해야 하며, 측정 중 오버레이를 다시 열면 **그 세션은 무효로 표시**되어야 한다(F10 측정 시작 규칙). 측정 중 **일시정지(ESC)·타이틀로 나가기·오류 중단**이 일어나면(게임 진행 게이트가 닫히면) 그 세션도 무효로 표시되어야 하며 결과 파일에 무효 사유가 남아야 한다(일시정지 중에도 프레임은 돌아 FPS·GC 집계가 오염되기 때문이다). (11회차 보강) 현황 패널의 표시 여부는 거부 조건에 들어가지 않으며, 현황 패널은 오버레이와 함께 숨겨진다.
- (4회차 신규) 주어진 측정에서 적 수가 N에 도달한 뒤 300스텝은 통계 집계에서 제외되어야 한다.
- (4회차 신규) 주어진 개발자 모드로 측정 중일 때는 `runInBackground`가 켜지고 창 포커스를 잃어도 자동 일시정지가 일어나지 않아야 한다(F8).
- (4회차 수정, 11회차 보강) 주어진 측정 CSV 헤더에는 전략 조합, 적 수 N, 디스폰 거리 D, 시드, 구간별 몬스터 체력 배율 목록(11회차), 공간 해시 셀 크기, 측정 길이, 스텝 간격, 무적 여부, 고정 무기 구성(W1~W4 단계), 스폰 중단 + N 유지 모드 여부, 수직동기·`targetFrameRate`·스크립팅 백엔드·점진적 GC 설정, 제외한 워밍업 스텝 수, PC 사양(CPU, GPU, RAM, OS)이 기록되어야 하고, 본문 열에는 F10 6개 항목과 활성 젬 수가 들어가야 한다. **메모리는 측정 구간의 평균과 최댓값 두 열**이다(Q46, 기본값 채택). 파일은 UTF-8 BOM, 소수점은 InvariantCulture 형식이다(F11).
- (4회차 신규) 주어진 개발자 모드 사용법(활성화 `--dev`, F1 토글, 측정 절차)이 `README.md`의 전용 절에 문서화되어야 한다(F14 매핑 표).
- (8회차 신규) 주어진 게임 시간 즉시 점프는 **앞으로만**(목표 스텝 ≥ 현재 스텝) 허용되어야 한다. 뒤로 가는 점프는 거부하고 오버레이에 표시해야 한다.
- (8회차 신규) 주어진 개발자 "보스 즉시 소환"으로 10분 전에 보스를 처치하면 **클리어**로 처리되어야 하며(F8 연계), 36000스텝에 보스가 다시 등장하지 않아야 한다(보스는 판당 1기).
- (8회차 신규) 주어진 "공격 끔"은 새 발사·생성을 멈추고 **이미 존재하는 궤도 원·장판의 피해 판정도 멈춰야** 한다. 궤도 원은 표시만 유지된다.
- (8회차 신규) 주어진 핫 리로드(Q43) 뒤에도 **이미 보유한 무기·패시브 인스턴스는 로드 당시의 정의를 그대로 써야** 한다. 강화 후보와 단계 수(5단계 여부 판정)도 그 정의 기준이며, 새 파일에서 삭제된 무기의 보유 인스턴스도 유지되어야 한다.
- (11회차 신규, 12회차 수정) 주어진 오버레이가 열려 있는 동안 현황 패널에 보유 무기·패시브와 레벨(진화 무기는 `(evolved)` 표기 — 영어 레이블 원칙), 현재 스폰 구간의 몬스터 체력 배율(구간 밖 스텝에서는 F03의 "가장 최근 구간 배율" 규칙의 값으로 HUD와 같은 값), 게임 시간과 스텝 번호, 판 시드, 생존 몬스터 수(보스 포함), 활성 젬 수, 현재 전략 조합 4종, 실제 배속이 모두 표시되고 매 프레임 갱신되어야 한다. 오버레이가 닫혀 있으면 현황 패널의 렌더링·수집 비용이 발생하지 않아야 하며(시각화의 "꺼져 있으면 비용 없음"과 같은 규칙), 현황 패널을 열고 닫는 것이 시뮬레이션 상태(3.0 F 결정론 기준 항목)를 바꾸지 않아야 한다.
- (11회차 신규) 주어진 오버레이의 고정 레이블은 영어여야 하며, 데이터에서 온 한글 문자열(무기·패시브 표시 이름)을 포함한 모든 텍스트는 OS 폰트 "Malgun Gothic"으로 렌더링되어야 한다. 그 폰트를 만들 수 없는 환경에서는 오류 없이 엔진 기본 폰트로 표시되어야 하며, 이때 한글이 깨져 보이는 것은 허용된다(개발자 도구이므로 폰트 자산을 추가하지 않는다).
- (12회차 신규) 주어진 무기 구성 즉시 설정에서 W1~W4 각각 단계 0~5를 지정할 수 있어야 하며, 0을 지정한 무기는 보유 목록에서 제거(미보유)되고 1~5는 그 단계로 보유되어야 한다. 적용 결과 보유 무기(진화 무기 E1·E2 포함)가 0개가 되는 설정은 거부되어 보유 구성이 바뀌지 않고 거부 사유가 커맨드 로그에 표시되어야 한다(Q50, 기본값 채택). 제거했다가 다시 넣은 무기는 비어 있는 슬롯 중 가장 앞 번호에 들어가야 하며, F07 진화 순서는 그 슬롯 번호를 기준으로 한다. 진화 무기는 이 설정으로 만들거나 지울 수 없어야 하며(진화는 F07 경로뿐), 진화 무기를 보유한 중에 그 원본 무기를 0 이외의 단계로 설정하는 요청은 거부되어야 한다(Q50, 기본값 채택). 적용된 설정은 다음 프레임 안에 HUD 패널(F08)과 현황 패널에 반영되어야 한다.
- (12회차 신규) 주어진 패시브 구성 즉시 설정에서 P1~P3 각각 단계 0~정의 데이터의 최대 단계를 지정할 수 있어야 하며, 0을 지정한 패시브는 미보유가 되고 1 이상은 그 단계로 보유되어야 한다. 적용된 설정은 무기 구성과 같이 다음 프레임 안에 HUD 패널(F08)과 현황 패널에 반영되어야 한다.
- (12회차 신규) 주어진 개발자 모드의 일반 스폰 켜기/끄기 토글을 판 진행 중에 누르면 판을 다시 시작하지 않고 **다음 스텝부터** 적용되어야 한다. 끔 상태에서는 스폰 테이블 스폰과 N 유지 재스폰이 모두 발생하지 않아야 하고, 보스 등장(10분)·보스 소환(패턴 ②)·"즉시 N기 생성"은 끔과 무관하게 동작해야 한다(Q50, 기본값 채택). 켬으로 바꾸면 그 스텝부터 스폰 테이블대로 재개하며, 꺼져 있던 동안의 스폰을 몰아 스폰하지 않아야 한다(F03 상한 보류분 "버림" 규칙과 같다). 토글은 스텝 명령으로 적용되어, 같은 시드에서 같은 스텝에 같은 토글을 넣은 두 실행의 결과가 같아야 한다(결정론 유지). "다음 판부터" 적용되는 기존 스폰 정책 설정(특정 종만 스폰·N 유지 모드)의 적용 시점은 바뀌지 않는다.
- (12회차 신규) 주어진 개발자 모드의 카메라 줌은 orthographic size를 4.5 이상 27 이하 범위에서 조정할 수 있어야 하고 범위를 벗어나는 값으로 바뀌지 않아야 하며, 리셋하면 9로 돌아와야 한다(Q50, 기본값 채택). 줌은 표시 전용으로 스폰 반경(20)·디스폰 거리·공간 해시 격자·판정 반지름을 바꾸지 않고 시뮬레이션 상태(3.0 F 결정론 기준 항목)를 바꾸지 않아야 한다. 개발자 모드가 꺼져 있으면 orthographic size는 항상 9여야 한다. 줌 값은 측정 시작 거부 조건에 들어가지 않으며, 측정 시작이 기존 가드를 통과하면 카메라 줌을 기본 9로 자동 복귀시킨 뒤 측정을 시작해야 한다. 측정 중에는 오버레이가 숨겨져 줌을 조작할 수 없고, 오버레이를 다시 열면 기존 규칙대로 그 세션은 무효로 표시된다(Q50, 기본값 채택).
- (12회차 신규) 주어진 오버레이의 커맨드 로그는 최근 10줄을 최신 줄이 위로 오도록 표시해야 하며, 각 줄은 판 번호(세션 안에서 1부터) + 스텝 번호 + 명령 이름 + 결과(수행 또는 거부 사유)여야 한다(판 번호 덕분에 판을 넘어가도 줄이 구분된다). 사용자가 내린 모든 개발자 명령(수행·거부 모두)이 로그에 남아야 한다. 로그는 새 판 시작 시 지워지지 않고 세션(프로그램 실행) 동안 유지되어야 하며 파일로 내보내지 않아야 한다(충돌 이벤트 로그·측정 CSV와 별개, Q50, 기본값 채택). 로그 기록·표시는 시뮬레이션 상태(3.0 F 결정론 기준 항목)를 바꾸지 않아야 한다. 명령 기록은 사용자 조작 시점 1회 일어나는 것이므로 "오버레이가 닫혀 있으면 표시 비용 없음" 규칙과 충돌하지 않는다.
- (12회차 신규) 주어진 상자 효과가 적용되면 그 결과(F04 12회차 "최근 상자 결과 목록")가 커맨드 로그에 명령 줄과 스텝 순으로 섞여 표시되어야 하며, 형식은 영어 고정 레이블 + 데이터의 `displayName`이다(예: "Chest: 투사체 Lv 3→4"). 상자 결과는 시뮬레이션이 목록으로 보관하므로 오버레이가 닫혀 있던 동안 적용된 결과도 오버레이를 열면 표시되어야 한다(Q50, 기본값 채택). 같은 스텝의 명령과 상자 결과는 명령 줄이 먼저, 상자 결과 줄이 뒤여야 하며, 상자 결과 줄에도 판 번호와 스텝 번호가 붙어야 한다. 시뮬레이션의 최근 상자 결과 목록은 새 판 시작 때 비워지지만, 이미 로그로 옮겨진 이전 판의 줄은 세션 동안 남아야 한다(Q50, 기본값 채택).
