### F12. 구조 문서(README)

**수용 기준**
- 주어진 저장소 루트의 `README.md`는 한국어로 작성되어야 한다. 코드 주석은 영어여야 한다.
- 주어진 `README.md`에 클래스 다이어그램 1개가 포함되어야 한다.
- 주어진 `README.md`에 주요 흐름도 1개가 포함되어야 한다 (총 다이어그램 2개).
- 주어진 다이어그램은 Mermaid(텍스트 기반)로 작성되어야 한다. GitHub README가 직접 렌더링하고 diff로 추적되기 때문이다.
- 주어진 `README.md`에 설계 이유(왜 전략 인터페이스로 분리했는지, 왜 JSON을 선택했는지, 왜 개발자 모드를 별도 컴포넌트로 뒀는지 등)가 서술되어야 한다.
- 주어진 `README.md`에 "코드 수정 없이 추가 가능"의 **경계**가 문서화되어야 한다: 기존 행동 타입의 파라미터·조합은 JSON만으로 가능하고, 새 행동 타입(예: 포위 AI, 벽에 튕기는 투사체)은 코드 추가가 필요하다는 것. (경계를 알고 그었다는 것이 설계 설명의 일부다.)
- 주어진 `README.md` 상단에 시연 GIF 1개가 있어야 한다 (F13 연계).
- 주어진 `README.md`에 시연 영상 링크, 빌드 다운로드(GitHub Releases) 링크, 실행 방법이 있어야 한다.
- (4회차 수정) 주어진 다이어그램이 실제 코드 구조와 일치해야 한다. 코드 구조가 바뀌면 문서도 갱신되어야 한다. **일치 판정 기준**: TECH_SPEC 5.0의 인터페이스 전부와 그 구현 클래스가 다이어그램에 나타나야 한다.
- (4회차 신규) 주어진 `README.md`에 게임플레이 기능(F1~F8)별 설계 이유가 기능마다 1단락 이상 서술되어야 하며, F19 개발자 모드 사용법 절이 있어야 한다(F14 매핑 표).
